# # Agent Directory & Routing Table

Read this index first to identify which contextual files must be loaded before executing any task.

Note: `01_SPECS/specs.md`, `02_CONTEXT/architecture.md`, `02_CONTEXT/business-logic.md`, and the `03_TRACKING/` files below refer to *this vault-root harness system's own* files. CSOM (`02_CONTEXT/skills/csom.md`) produces separate, identically-named files scoped to `PROJECTS/<slug>/` for each individual project, those are not the same files and are never written here.

## Core & Execution Controls
* `00_CORE/prompt.md`: The main Ralph Loop system prompt. Read when starting an automated execution cycle to retrieve the step-by-step iteration guidelines.

## Specifications & Task Tracking
* `01_SPECS/specs.md`: Active feature specification and checkbox task list. Read at the start of every iteration to pick the highest-priority unfinished unit. Tick items upon completion.
* `01_SPECS/tasks/`: Local branch task archives. Read the folder corresponding to your git branch name when investigating past implementation choices or branch-specific specs.

## System Context & Boundaries
* `02_CONTEXT/architecture.md`: Project tech stack, structural patterns, directory maps, and file pointers. Read before creating components, APIs, or database schemas.
* `02_CONTEXT/business-logic.md`: Domain logic, user roles, workflows, and business rules. Read when implementing core features to ensure functional compliance.
* `02_CONTEXT/skills/`: Reusable procedural guides (e.g., database migrations, API creation). Read the specific skill file relevant to your current sub-task before writing code.
* `02_CONTEXT/skills/csom.md`: Turns a rough hackathon idea into a documented, scored decision, writing directly into a per-project mini-harness at `PROJECTS/<slug>/` (its own `00_CORE/overview.md`, `01_SPECS/specs.md`, `01_SPECS/tasks.md`, `02_CONTEXT/architecture.md`, plus `business-logic.md`/`blocked.md`/`learnings.md`/`tech-debt.md` where relevant). Read this when the user wants to plan a new project from an idea, before any coding starts.
* `02_CONTEXT/skills/project-doc.md`: Reads a CSOM-populated `PROJECTS/<slug>/` folder, adds technical depth to the architecture, synthesizes `03_TRACKING/risks.md`, and assembles a self-contained `PROPOSAL.md`. Read this after CSOM has finalized a project's files, or when the user asks for a project proposal document.
* `02_CONTEXT/rules/`: Strict, non-negotiable code rules, syntax standards, and security boundaries. Read before committing code; never violate these constraints.

## System Tracking & Feedback
* `03_TRACKING/tech-debt.md`: Documented engineering compromises and workaround markers. Read when refactoring or working near existing technical debt. Log intentional debt here.
* `03_TRACKING/learnings.md`: Historical record of edge cases, bug fixes, and system quirks. Read when troubleshooting errors or encountering unexpected behavior. Append new learnings after fixing complex issues.
* `03_TRACKING/blocked.md`: Handbrake file. Write the exact issue here and HALT execution immediately if blocked by missing credentials, third-party outages, or missing human input. Never invent mock data.
* `03_TRACKING/review-findings.md`: Audit reports generated by automated background reviewers. Read when assigned to a system cleanup, refactoring, or documentation audit task.

## Execution History
* `04_LOGS/execution-logs/`: Verbose per-iteration execution outputs. Read specific iteration log files when debugging why a previous run failed or went off track.
